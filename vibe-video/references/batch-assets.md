# 脚本 → 批量素材 → 用户验收 → 文件夹交付

适用于只制作素材，也可作为完整视频制作的素材阶段。默认由当前智能体编排内置工具；本地脚本只负责预览和打包，不把内置生图伪装成可在 Python 中调用的 API。

## 1. 拆清单并保存进度

读取完整脚本及文末图片/动图表，优先保留已有编号、子编号、中文名称、时间段、复用来源和明确“不做”的项。没有清单时根据分镜补齐，不能把一个编号的多张变体漏成一张。用户已有脚本时不重新扩写选题。把实际计划保存为项目根目录的 `素材任务.json`，字段见文末。

把画风、角色身份、参考图、道具、透明/完整背景、朝向、比例和动作终点固定下来。已有系列时先查看该系列图片；同一人物之后始终带参考，不能只靠风格词。参考图和复用素材复制进当前项目，记录来源与哈希。不要把某一系列的“灰蓝卫衣、两个点眼睛、无嘴”当作所有题材的默认人物；历史人物、背景群像按脚本独立约束。

图片、动作、封面分项记录。已有脚本里的“必做 → 建议 → 可选”是**镜头优先级**，下面的渠道顺序是**供应渠道优先级**，两者不能混为一谈。可选项按本次授权范围处理；不在范围的项标为暂缓并说明。每次提交、落盘、检查、用户决定后保存 JSON；中断恢复时先查任务号、现存文件和哈希，只补未完成项。

## 2. 使用内置 AI 生图分批完成

1. 发现当前环境的内置图像生成工具（例如 `image_gen`）；如有对应 imagegen skill，遵循其真实工具参数。用户要求内置生图时不改用收费 API 或 CLI，不要求 API Key。工具不可用就明确记录阻塞。
2. 先完成角色/关键道具参考，再按依赖生成其余素材。每项一个独立调用和独立成品，不能用一张多宫格替代多个组件。可按角色、道具、背景分成便于检查的小批次；在工具支持且参考无依赖时并发，不固定声称支持某个并发数。
3. 每条提示词包括该项内容、全片画风、参考图各自作用、朝向、比例、背景和禁止项。先查看本地参考图，再按当前工具 schema 传参考；不要虚构 `batch_size`、`output_path`、模型名或原生分辨率参数。透明组件请求真实透明背景，完整场景不抠图。
4. 每项结束立即保存到项目目录，文件名 `编号_中文名.png`，记录实际生成工具、提示词、参考来源、原生尺寸、交付尺寸和 SHA-256。工具只返回图像而无可读文件时，用宿主支持的保存能力；无法保存就报告，不能捏造路径或说已落盘。
5. 批次结束查看联系表，检查角色五官/衣服、道具数量、方向、完整轮廓、结构、无多余文字与 alpha。只返工有问题的编号，原件与候选分开保留。每项默认最多一次有针对性的质量返工；仍失败记录缺项，继续不依赖它的素材。

用户说“全部制作”已授权连续完成各批，不在每批末尾问是否继续。生成成功不等于落盘成功；尺寸适配、放大或补帧必须标为后处理，不说“原生2K/1080P”。内置生图依赖活跃会话，不能承诺关闭会话后继续调用；依靠持久清单续作。支持独立运行的外部队列则使用持久进程并保存任务号与日志。

封面只在任务包含时生成：沿用已确定的角色和本片画风，横版4:3、竖版3:4分别构图，核对实际像素比例及标题。这里允许用户要求的标题，不沿用片内组件的“无字”限制；保留安全区，但不声称已通过平台自动裁切测试。

## 3. 按预设优先级尝试动图

开始前把本次顺序、预算与限制写入 `generation`。下面是默认配置，用户本次指定优先于它；端点、模型权限、价格、免费积分和重置时间均需实时核对，不复制历史账号数据。

| 顺序 | 路线 | 执行与退出条件 |
|---|---|---|
| 1 | Hugging Face ZeroGPU 图生视频，优先 Wan 路线 | 核对当前 Space 运行状态、实际接口与账户额度。需要首尾帧且 Wan 入口不支持时，可在同一 HF 路线中选支持首尾帧的 LTX 等入口；不要编造接口参数 |
| 2 | PixVerse 已确认的免费额度 | 优先已安装插件及其 CLI 包装器；读当前插件说明并预检身份、权限、预计消耗和免费余额。默认360P、约4秒、无音频，以本次用户规格和当前模型支持为准 |
| 默认关闭 | 付费渠道 / 本地模型 / 本地二维替代 | 仅在用户已授权对应费用、硬件执行或替代方式时加入队列。二维版必须标为候选，不能悄悄充当模型动画或合格动作 |

零新增费用是默认上限；免费额度来源不明或与付费余额混用且无法区分时，不假定免费。不得自动充值、订阅或切到付费 fal 等服务。HF 的额度属于个人账户，换 ZeroGPU Space 不会产生新额度；额度耗尽就跳过整条 HF 路线，继续已获授权的其他路线。参考[官方额度说明](https://huggingface.co/docs/huggingface_hub/main/guides/manage-spaces#track-your-zerogpu-quota)，使用当前安装版本支持的查询方式。

每条动图按“必做 → 建议 → 可选”处理；先用一个有代表性的动作验证新路线，再按授权继续同类任务。新路线样片先通过技术和动作自查；只有用户要求先看样片，或需要改变费用/质量/替代方式时，才增加中途确认。每个镜头每条路线默认至多2次实际生成（首试 + 一次针对失败原因的修正），不无限重抽。明确失败后可换下一条路线；余额/配额耗尽直接停用该预算域。请求结果不明时先查任务号，未确认失败不得重复提交或换渠道生成同一条。

**每次生成必须落实的动作约束：**对应静图作首帧；终点明确且模型支持时加尾帧；镜头固定；只让指定部位动；人物朝向和身份不变；手与道具保持接触；机械固定部分不变形；主体全程不出画。循环动作检查姿态和速度接点，单次动作检查结束停留；不能用倒放强行循环不可逆动作。透明格式优先 WebM/MOV，模型不支持 alpha 时使用均匀绿幕或其他适合主体颜色的背景再抠像。GIF仅在用户要求时附加预览。

额度耗尽或所有路线失败：记录 `blocked` / `failed` 和缺项，保留已完成成果与任务号。用户同意暂缓后可交付其余素材；不自动建立提醒、监控或日后重试任务。

## 4. 自查与用户验收分开

技术检查包括静图完整解码、尺寸/比例、非空主体、真实 alpha；动图完整解码、时长/帧数/帧率、音轨、逐帧 alpha、循环接点或单次结束停留。VP9 透明解码需使用支持 alpha 的解码器，例如 FFmpeg `libvpx-vp9`；仅看扩展名或元数据不够。抠像后在深浅背景检查边缘与残点，避免把主体颜色抠除。

视觉检查重点：动作是否真的发生、镜头是否漂移、五官/肢体是否新增、方向是否改变、手机或拉杆是否消失/脱手、硬质结构是否变形。技术通过只写 `qa: passed`；`decision: accepted` 必须来自用户对当前文件版本的接受。自动脚本不判断动作质量。

使用下列命令生成可查看的总览（路径替换为实际 skill 安装目录；manifest 内路径相对其所在目录）：

```bash
python3 /path/to/vibe-video/scripts/deliver_assets.py preview 素材任务.json 素材总览.html
```

预览显示编号、制作方式、技术状态、用户决定及限制；图片有棋盘底，页面可切深浅底，动图有播放控件。浏览器不支持透明格式时附加底色 MP4 预览并注明它不是透明源文件，同时给原文件下载链接。提供此总览让用户验收，未回复、等待超时或预览被打开都不算同意。不要伪造用户话语。

将用户的决定逐项记录为 `accepted` / `excluded` / `deferred`；弃用或暂缓必须有理由，仍为 `pending` 的项不能打包。用户只接受静图时不顺带接受动图；用户明确“不要动03，其余通过”可据此记录其余当前预览项。弃用动图不自动弃用其静图。

## 5. 验收后自动打包，不压缩

记录用户原意与时间到 `review.note`。更新逐项决定后再运行 `preview` 刷新清单快照，将其输出的 `selection_sha256` 写入 `review.selection_sha256`，设置 `review.status: approved`，随即执行，无需另问是否打包：

```bash
python3 /path/to/vibe-video/scripts/deliver_assets.py pack 素材任务.json 视频名称-上传素材包
```

脚本只复制 `accepted` 且 `qa: passed` 的列明文件，按图片组件、动图组件、封面、说明附件归类，生成 `使用说明.md`、`素材清单.csv`、`打包校验.json`。校验批准快照、源文件及副本哈希；拒绝路径越界、符号链接、隐藏文件、重复目标名和覆盖现有输出。不扫描整棵制作目录，因此未列入的旧版、失败版、预览、缓存不会混入。发布包中不带账号凭据或调试日志。

文件变更后原验收哈希失效；改动素材需要用户重新查看接受。已有交付文件夹保留，补封面或改素材时输出 `-v2` 等新目录，避免污染上一次交付。复制异常会留下未完成目录和标记，不能当作成品；修复后使用新目录重试。缺项和弃用项写进使用说明。封面、WebM与MOV各算文件，WebM与MOV属于同一动图，不把格式副本当成额外动作数量。完成后提供真实目录链接与数量；整理文件夹不等于上传到外部平台。

## 清单示例与状态

以下是结构示例，不是已验收成果。智能体按真实脚本填充，生成前 `files: []`，成功落盘后填写实际路径及64位 SHA-256。`preview` 和 `pack` 只读取清单，不替用户批准或发起模型调用。

```json
{
  "project": "示例短片",
  "script": "分镜脚本.md",
  "generation": {
    "image_tool": "builtin",
    "motion_priority": ["hf-zerogpu", "pixverse-free"],
    "max_new_spend": 0,
    "pixverse_resolution": "360P",
    "max_attempts_per_route": 2,
    "allow_local_2d_fallback": false
  },
  "review": {"status": "pending", "note": "", "selection_sha256": ""},
  "assets": [
    {
      "id": "01", "name": "主角参考图", "kind": "image",
      "priority": "required", "state": "planned", "method": "builtin-image",
      "prompt_file": "提示词/01.md", "reference_files": [],
      "native_size": null, "delivered_size": null,
      "qa": "pending", "decision": "pending", "notes": "",
      "files": []
    },
    {
      "id": "动01", "name": "主角点头", "kind": "motion",
      "priority": "required", "state": "planned", "method": "",
      "source_ids": ["01"], "loop": true, "attempts": [],
      "qa": "pending", "decision": "pending", "notes": "",
      "files": []
    }
  ]
}
```

`kind` 支持 `image`、`motion`、`cover`、`document`；`files` 中每项为 `{"path":"图片组件/01_主角.png","sha256":"实际64位哈希"}`。选入的文件都是交付文件，原始模型文件和弃用候选在另处保留；可选 `preview` 字段指向项目内底色视频。`attempts` 保存渠道、实际模型、任务号、起止时间、状态、实际额度消耗和错误摘要，不含 token、cookie 或带凭证的下载 URL。

生成状态依次为 `planned → generating → ready`，或进入 `blocked / failed`；`ready` 只表示文件已保存。技术状态为 `pending / passed / failed`，用户决定为 `pending / accepted / excluded / deferred`。恢复时 `generating` 项先查远端任务，`ready` 项校验本地文件；不能批量重置队列重新扣额度。

## 已有制作经验带来的约束

- **稳定身份比同一画风词更有效**：组件与封面共用人物参考；历史人物、背景人物不能无条件换成主角。
- **可解码不代表动作合格**：二维光流曾出现朝向漂移、手势失真、机械变形。模型失败后保留缺项，比将这种候选写成已完成更准确。
- **尺寸与来源要透明**：保留原生文件，交付放大或插帧单独记录；技术验收、用户认可、最终工程适配分别报告。
- **下载失败不等于生成失败**：外置盘遇到 hard-link `ENOTSUP`，先按原任务号下载到可用临时盘，再复制到项目并比对哈希，不重新提交生成。
- **交付以用户最终选择为准**：拒绝的动图即使技术检查通过也排除；静图可独立保留。只打包清单中的接受版本，避免旧版和 macOS `._*` 混入。
