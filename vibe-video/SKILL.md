# vibe 视频：从选题到发布

这是用户「vibe 视频」项目里做了 8 支片子攒下的经验。片子是 Remotion 做的知识类动画短片（「Web 知识大赏」那一路），175 秒，纯字幕，发 B站、抖音、小红书。

## 这个 skill 里有什么，什么时候读

| 文件 | 什么时候读 |
|---|---|
| `SKILL.md`（本文件） | 每次都读：用户口味、硬规矩、选题、脚本、磨稿、交付、文案 |
| `references/remotion.md` | 动手做画面、渲染、混音、出片打包时；含 13 条踩过的坑 |
| `references/review.md` | 每支片子交付前、用户报穿帮后改版时：逐帧审片清单 |
| `references/benchmark-checklist.md` | 磨脚本和审片的原始标准，「生与死」线程自己写的，每条带真实例子 |
| `assets/starter/` | 找不到上一支源码包时的起手工程，`npm i` 后能直接出图 |
| `scripts/` | `mix.py` 多路音效 + BGM 压低、`splice2.py` 局部重渲按帧拼回、`gen_clicks.py` 按画面曲线合成音效、`cutout.py` 抠图 |

## 一支片子的顺序

1. 选题（第三节）→ 用户选中。
2. 写分镜脚本（第四节）→ 先自己磨，再请「生与死」磨两轮（第五节）→ **给用户过目，点头才做画面**。
3. 起工程、逐场做画面，每做完一场抽帧自查（`references/remotion.md`）。
4. 分段渲染 + 混音 → 全片每 2 秒抽帧，按 `references/review.md` 自己挑一遍 → 请「生与死」逐帧挑错 → 修完复核。
5. 交付 + 三平台发布文案（第六、七节）→ 更新项目记忆（第八节）。

## 一、用户是谁、要什么

- 中文，说话简洁幽默、可以锐评毒舌。**不会写 prompt，片子全权交给 Claude**：画面细节自己拿主意，别拿一堆小问题去问用户。
- 审美标准（用户原话的意思）：
  - 「高级、有深度、引人深思」，对标 `/mnt/project-files/参考视频.mp4`：黑底金字、宋体、左上年份/场记、右上文献印章、底部逐字字幕金色高亮、具象物件配科普叙事。
  - **画面要塞满**：元素多、动画组件丰富、冲击力强。用户骂过「空白多、元素少」「视觉单调」（v1 只有粒子被打回）。只有粒子不行，要有骰子那样的**具象物件**。
  - **开场短**：6 秒左右进片名，10 秒是上限（第 1 支 v1 拖到 30 秒被骂）。
  - **运镜和转场要优雅**：缓推、拉远、横摇、景深；跨度大的叙事跳跃中间要搭桥（原子→分子之间补了米勒-尤里实验）。
- 用户**逐帧挑穿帮**：人和道具遮挡/错位、字出框、字被压、圈没圈准、文字没在框或两道界行正中、问号压字、版心字不居中。一个问题出现，用户默认全片同类都有，**修的时候全片同类元素一起查**，不能只改用户指的那一处。
- 用户给的参考图/素材必须**高度还原**（可以做成粒子），还原不到位观众 get 不到梗。复杂具象物（神兽、名画、人手、人脸）**不要用 SVG/代码手画**，用户嫌丑，会自己 AI 生图或抠图补；用户给的现成图直接用，融进画面不违和。
- 用户自己的猜想要放进片子，但**盖「猜想」章**；转述别人的推测盖「推测」章。用户很认这种严谨。

## 二、硬规矩（每支都一样，除非用户另说）

| 项 | 规定 |
|---|---|
| 时长 | 175 秒，配满 `/mnt/project-files/背景音乐.mp3`（《若如初见》），结尾淡出 |
| 规格 | 1920×1080、30fps、5250 帧 |
| 声音 | 纯字幕，**不配音**（容器也连不上 edge-tts）。音效可以加（快门声、笑声原音、计数器咔哒），压在 BGM 下 |
| 交付 | 分享版 mp4 + 1080p 高清版 + 工程源码 tar.gz（不含 node_modules）+ 发布文案.md + 分镜脚本.md |
| 位置 | `/mnt/project-files/第N支/`，改版**同名覆盖**为最新版（大改可留 _v1 档），在回复里说清楚 |
| 流程 | 先选题 → 出脚本给用户过目 → **用户点头才做画面** → 成片 → 逐帧挑错 → 交付 → 发布文案 |

## 三、选题

用户挑题很挑，常要两三批候选才中。先读 `/mnt/project-files/第*/选题候选.md` 看哪些被否过、项目记忆里的备选库，避开撞题。

**中的路数**
- 片名本身是个谜面，答案落在**观众自己身上**（主角是「你」）。
- 有真实故事或硬事实，有反转，看完沉默几秒。
- 「天天经历却说不清为啥」、老话背后的科学、细思极恐的反转谜面（用户自己出的题多是这类：楚门的世界是拍给我看的吗、友谊悖论）。
- 人人都在经历却没察觉的一种「失去」+ 一个能当片名的谜面（流量最高的两支：《沉船里的钢》「2022 年以前的字成了沉船里的钢」、《一年过得越快》「时间没变快，是你不再按快门了」）。
- AI 续集不算禁区。

**不中的路数**：科普冷知识清单、心理学教科书式效应、宇宙宏大向、外国人/古人/动物的故事（离观众远）、日常情感鸡汤、「两件不相干的事是同一件」、算账式解释（「凑不出 200 小时」被嫌没深意）、营销腔。

**怎么出候选**
- 一批 5–9 个，每个一行谜面 + 一句立意（落在「你」）+ 硬事实出处 + 画面信物。标 ★ 首推、次推，说为什么。细节写进 `选题候选.md`（同目录追加「第 N 轮」）。
- 整批被否：先复盘用户选中过的片子的共同点，**说出诊断**再换方向，别换汤不换药。卡住时问用户哪支流量好，或者让用户丢一个觉得有意思的视频。
- 用户自己出题时直接接住，不再推销候选。

## 四、分镜脚本

文件：`/mnt/project-files/第N支/分镜脚本.md`。照第 6–8 支的格式（`第8支/分镜脚本.md` 是最新样板）：

1. 抬头一行：规格、BGM、纯字幕、版式（左上 HUD、右上引用和印章、底部逐字字幕每屏最多两行每句至少 1.5 秒）、第几秒进片名。改版在抬头写清吸收了哪轮意见。
2. **一句话立意**，加粗金句。
3. **反转**（一到两个），以及它们在结尾怎么接上。
4. **美术**：配色和颜色语义（一个颜色只表达一个意思，例如锈金=人、冷青=AI、暗红只给那颗暗星），母题，字体，氛围层，**不画人脸和手**（用物件、背影代替），不做真实 App 界面。
5. **主线**：一个贯穿全片的具象**信物**（碳原子、金色胶片、红线、探照灯光斑、同学录、计数器），加一条 HUD 暗线（计数器/直播观众数这种会在结尾翻转的数字）。
6. **BGM 和节奏表**。《若如初见》的结构：0–14 安静前奏 / 14–36 起势 / 36–92 第一个高潮 / 92–108 全曲最安静的低谷 / 108–158 第二个高潮 / 158–175 收尾（171.5 起淡出）。反转放高潮，最安静的戏放低谷。
7. **分镜表**：时间 | 章节 | 画面 | 字幕。字幕里 `【】` 标金色高亮的「刀子」，冷色另用一种括号。
8. **转场**（全片一个招牌转场 + 匹配剪辑清单，不和前几支撞：快门、穿针、擦锈、布景板、声波都用过了）、**运镜**、**3D/2D/具象物件清单**（每屏一个具象物件）、**事实依据**（每条：出处、年份、片中怎么措辞、哪里不能加码）、**和前几支的区别**、**留给你拍板的地方**（最多两三条）。

**写作上起作用的**
- 第二人称「你」。把冷知识翻译成和你有关的话（「你的一生，只是除夕夜的最后 0.18 秒」）。
- 一个可以截图转发的核心意象（「你是一个漩涡」「古人谓之异兽，今人谓之梗」）。
- 首尾镜像回扣（「你觉得所有人的朋友都比你多 / 有个人，也是这么看你的」）。
- 结尾一刀落在「你」身上，但**不替观众做决定**（暗红星不变亮，不递糖、不号召）。
- 可以暗藏一处自省：这支片子本身是 AI 做的（句号闪一下、计数器响一声），不说破。
- 数学、术语只当谜面，前 50 秒讲完，后面全给人。
- 引用控制在 5 个左右，太多像清单。每个都要核实，事实措辞不加码（「很多在」「推测」），说不清的砍掉。
- 不用「细思极恐」之类营销腔。

**发给「生与死」之前先自己按它的标准磨一遍**
- 结尾和反转在逻辑上打不打架：前面推翻了什么，结尾就不能站在被推翻的立场上（第 8 支 v1「只要教我的是个人」被第一个反转「AI 腔也是人教的」驳倒，改成「叫得出我的名字」）。
- 金句会不会被评论区一句话杠倒（「它叫不出你的名字」→「它什么都会说，就是不知道，自己在跟谁说话」）。
- 第一个反转要回收开场，让观众发现片子第一句就中招了。
- 加一句把两条线缝起来的狠话，讽刺式最好（「压下来的那条线，本来也是一种方言」）。
- 同一章连着 4 块以上「研究说/数据说」就是清单感，砍到 3 块以内或合并成一拍。
- 承载立意的那两句至少给 9 秒，时间从清单段里挤。
- 中英文、两个领域之间跳跃要有一句字幕当桥（「"深入探讨"，翻成英文，就是 delve」）。
- 术语不上字幕，换成看得见的动作（「限幅」→ 波峰上的「吃了冇」当场被改写成「吃了吗」）。
- 续集只借前作两样道具；彩蛋要有逻辑（生日 11 月 7 日配天蝎座，写错比不写还糟）。
- 事实核查：引语和原文一致，宁可转述不加引号；数字留余量（周活 8 亿写「每周几亿人」）；有争议的年份不写死；不说过头。

## 五、和「生与死」线程协作（质量标杆）

「生与死 Remotion 视频」线程（session `cse_01SNWoLkmckod8PaLtKub6nD`，已 resolve，发消息会自动叫醒）做的第 1 支是用户的质量标杆。用户要求新片和它**深度双向交流**：
1. 开工前把方案草稿写成 `第N支/方案草稿_给生与死.md`，`send_message` 请它锐评。**session id 原样照抄 `cse_` 前缀**，改成 `session_` 会假送达。等不到回复就用 `list_events` 去读它的记录。
2. 脚本让它磨两轮（v1 → v2 → v2.1），它砍的、加的都写进脚本抬头。
3. 成片后把抽帧（全片每 2 秒一张，结尾和关键反转加密到每 0.2 秒）发给它逐帧挑错，修完再请它复核一轮。第 5/6/7 支它分别多挑出 8/18/34 处，第 8 支 6 条大问题加 30 多处细节。审片标准见 `references/review.md`。
4. 用户说「不用复核」就直接交付。

## 六、交付

- 回复里给 `/mnt/project-files/...` 路径链接。分享版、源码包、文案放 `attached_outputs`；高清版常 800MB+ 挂不上，只给路径。交付前 `ls -la` 确认文件真在共享文件夹（第 1 支高清版漏拷过）。
- 回复结构：一句话说做好了 → 文件链接 → 「改了什么」几条（具体到画面）→ 请用户逐帧挑，哪一秒不对报时间点。
- 长渲染期间**定时 `update_status` 报真实进度（第几段/第几帧）**。后台跑渲染时线程显示「空闲」，用户以为卡住来问过。

## 七、发布文案

文件 `第N支/发布文案.md`，B站、抖音、小红书三版。用户要求：**1000 字以内但要写详细**，片子节奏快，观众靠文案补信息。

- **B站详细版**：标题（谜面 + 丨 + 钩子）；简介 800–1000 字，按片子章节把每段讲的事、真实出处、反转摊开讲，片中一闪而过的经文/数据在这里讲透；末尾列片中引用和「猜想/推测」标注；标签。可提醒 BGM 在 B站可能被提示版权。
- **抖音**：短，一句钩子 + 几行事实 + 金句 + 一个互动问题 + 话题标签。
- **小红书**：第一人称讲由来（「昨天在群里打出……发完愣了三秒」），📌 列三四条硬料，金句，结尾抛问题请评论区聊。
- 另给一句**封面字**（用核心意象，比片名更勾人）。
- 贴着片子本身的主线和金句写，**别写成营销号腔**。用户要能直接复制的版本时，用 `post_widget` 的 `writing_draft_v0` 卡片，同时存进 md 文件。

## 八、收尾

- 更新项目记忆：`MEMORY.md` 片单一行（片名、目录、核心意象、状态），细节写进该片的 team 记忆文件（选题过程、已核事实、生与死意见、工程坑）。
- 用户回反馈后改版，按 `references/review.md` 的方式全片同类一起查。
